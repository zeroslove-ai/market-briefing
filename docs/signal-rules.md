# 신호·백드롭·검증 계산 규칙

모두 결정적(deterministic) 계산입니다. LLM 추론이 개입하지 않습니다.

## 시장 백드롭 (market_backdrop)

지수 4종 + 반도체 ETF + VIX 조합으로 -100~+100 점수를 산출합니다.

```python
score = (S&P% × 12) + (나스닥% × 10) + (다우% × 8) + (러셀2000% × 10)
        + (SOXX% × 4) - (VIX 변동 × 3)
```

| 점수 구간 | 레이블 |
|---|---|
| ≤ -60 | strong_bearish (약세 가속) |
| -60 ~ -45 | bearish (약세) |
| -45 ~ -20 | slight_bearish (약한 약세) |
| -20 ~ +20 | neutral (혼조) |
| +20 ~ +45 | slight_bullish (약한 상승) |
| +45 ~ +60 | bullish (상승) |
| ≥ +60 | strong_bullish (상승 가속) |

브리핑에서 개별 신호가 백드롭과 **역행**하는지 **동조**하는지 함께 언급합니다.

## 비정상 OI 감지 (oi_anomalies)

CBOE 옵션 체인에서 콜/풋 총 OI를 분리 집계한 뒤, 전일 스냅샷(`flow_oi_snapshot.json`)과 비교합니다.

```python
call_oi_chg = (오늘 콜 OI - 전일 콜 OI) / 전일 콜 OI × 100
put_oi_chg  = (오늘 풋 OI - 전일 풋 OI) / 전일 풋 OI × 100
```

| 조건 | 판정 | 의미 |
|---|---|---|
| 풋 OI ≥ +10% **and** 주가 ≤ -1% | 🔴풋 | 신규 숏 베팅 (하락 베팅 유입) |
| 콜 OI ≥ +10% **and** 주가 ≥ +1% | 🟢콜 | 신규 롱 베팅 (상승 베팅 유입) |

> 주가 등락은 **Yahoo 정규장** 기준입니다 (CBOE 가격은 애프터마켓 오염 — pitfalls 참고).

## 컨빅션 스코어 (0–100)

```python
score = min(|OI변동%| / 50, 1) × 35      # OI 급증 강도
      + min(|주가변동%| / 5, 1) × 30      # 주가 움직임 강도
      + min(iv30 / 1.0, 1) × 20           # IV 레벨 (높을수록 기대 변동 큼)
      + (15 if 1σ 이탈 else 0)             # 시그마 이탈 보너스
```

**방향 판정** (먼저 매칭되는 조건 채택):
- `bullish` — 콜 OI ≥ +10% and 주가 ≥ +1%
- `bearish` — 풋 OI ≥ +10% and 주가 ≤ -1%

상위 4개(방향별)를 신호 종목으로 보고하고, 전체 해당 종목은 비정상 OI 목록으로 별도 보고합니다.

## 1σ 이탈 (sigma_breakout)

```python
1SD% = iv30(소수) × √(30/365) × 100
sigma_breakout = |일간 등락%| > 1SD%
```

예: iv30 = 96.42% → `0.9642 × √(0.0822) × 100 ≈ 27.64%`
→ 하루에 ±27.6% 넘게 움직이면 1σ 이탈.

## 결과 검증 (verification)

전일 실행에서 저장한 신호(`flow_signals.json`)를 다음 실행에서 검증합니다.

```python
close_pct = (당일 종가 / 신호 시점 가격 - 1) × 100
high_pct  = (당일 고가 / 신호 시점 가격 - 1) × 100
low_pct   = (당일 저가 / 신호 시점 가격 - 1) × 100
```

| 판정 | 조건 |
|---|---|
| hit (적중) | bullish & close_pct > 0, 또는 bearish & close_pct < 0 |
| miss (빗나감) | 위 조건 불충족 |
| flat (보합) | \|close_pct\| < 0.5 |

> 신호 시점 가격과 검증 가격이 **모두 Yahoo 정규장**이어야 비교가 성립합니다.
> CBOE 가격으로 신호를 만들면 애프터마켓 가격과 정규장 종가를 비교하게 되어 가짜 miss가 나옵니다.

## 스냅샷·신호 저장 규칙

| 파일 | 용도 | 갱신 시점 |
|---|---|---|
| `flow_oi_snapshot.json` | 전일 콜/풋 총 OI (61종) | **close 모드에서만** |
| `flow_signals.json` | 전일 신호 (ticker/direction/score/signal_price) | **close 모드에서만** |

- `open` 모드는 **읽기 전용** — 스냅샷·신호를 갱신하지 않습니다 (하루 2회 실행 시 비교 기준이 꼬이는 것을 방지)
- 증시 보고용 `oi_snapshot.json`과 **별도 파일**입니다 (두 스크립트가 같은 파일을 쓰면 서로의 기준을 덮어씀)

## 첫 실행 동작

첫 close 실행은 스냅샷이 없어 OI 비교가 불가능하므로 **신호 0건이 정상**입니다.
스냅샷이 프라이밍된 다음 실행부터 신호가 생성되고, 그 다음 실행부터 결과 검증이 붙습니다.
