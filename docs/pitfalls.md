# 실측으로 발견한 함정과 우회

운영 중 실제로 발생한 문제와 해결책입니다. 대부분 "데이터가 그럴듯해 보이지만 틀린" 유형입니다.

## 1. CBOE 가격은 애프터마켓/프리마켓을 반영한다 ⚠️ (가장 중요)

### 증상
브리핑에 실제로 없었던 급등이 신호로 잡힘.

| 종목 | 브리핑(CBOE) | Yahoo 정규장 실제 |
|---|---|---|
| TEAM | +30.4% 급등 | **-2.78%** |
| ABNB | +9.1% 급등 | **-0.56%** |
| DOCS | +78.3% | **-4.48%** |

### 원인
CBOE `data.current_price` / `data.price_change_percent`는 정규장 종가가 아니라 **최신 체결(애프터마켓·프리마켓 포함)** 기준입니다. 실적 발표 후 시간외 급등이 그대로 들어옵니다.

### 2차 피해 (더 위험)
신호 시점 가격이 애프터마켓 값으로 저장되면, 결과 검증은 Yahoo 정규장 종가와 비교하게 되어 **가짜 miss**가 나옵니다.

```
CBOE 신호가격 36.8(시간외) vs Yahoo 종가 20.66(정규장) → -43.2% miss (허구)
실제: -4.48%
```

### 해결
- **가격·등락은 Yahoo 정규장(`yahoo_quote`)을 정본**으로 사용
- **CBOE는 OI/IV30만** 사용 (`fetch_cboe`가 price 필드를 아예 반환하지 않도록 설계)
- 신호 시점 가격(`signal_price`)도 Yahoo 값으로 저장 → 검증 기준 일치

## 2. CBOE 병렬 대량 호출 → 429

### 증상
61종을 8스레드로 병렬 조회 → 전 종목 429 → 스냅샷 0종 저장 (조용히 실패).

### 해결
- **순차 호출** + 호출 간 1.5초 대기
- 429 수신 시 10/30/60초 백오프 재시도 (최대 4회)
- 실패 시에도 스크립트가 죽지 않고 해당 종목만 error 처리

```python
for attempt in range(4):
    try:
        d = json.loads(fetch(url, timeout=25)); break
    except urllib.error.HTTPError as e:
        if e.code == 429:
            time.sleep(10 * (attempt + 1)); continue
        raise
```

> 61종 순차 실행 소요: 약 2.5~3분 (429 백오프 없을 때 ~150초)

## 3. Yahoo 등락이 이틀 치로 계산됨

### 증상
"이틀 전 거 아니냐"는 지적. 등락이 실제의 약 2배로 표시.

### 원인
`range=2d`면 `meta.chartPreviousClose`가 **첫 캔들 이전 종가**(이틀 전)를 반환.

### 해결
`range=5d&interval=1d`로 요청하고 **캔들 배열의 마지막 2개 유효 종가**(None 제외)로 prev 계산. 데이터 기준일(`data_date`)도 함께 표기.

## 4. 스냅샷 파일 공유 충돌

### 증상
두 스크립트가 같은 `oi_snapshot.json`을 쓰면 서로의 기준을 덮어써 OI 변동이 0 또는 비정상으로 계산됨.

### 해결
스크립트별로 **별도 파일** 사용:
- `us_market_report.py` → `oi_snapshot.json`
- `option_flow_report.py` → `flow_oi_snapshot.json`, `flow_signals.json`

추가로, `open` 모드는 스냅샷·신호를 **갱신하지 않음**(읽기 전용). 하루 2회 실행되므로 open이 갱신하면 close의 비교 기준이 하루 안에 두 번 바뀌게 됨.

## 5. 첫 실행은 항상 신호 0건 (정상)

### 증상
첫 실행에서 "신호 없음" → 버그로 오인.

### 실제
전일 스냅샷이 없으면 OI 증감을 계산할 수 없음. 첫 실행은 스냅샷 **프라이밍**이고, 두 번째 실행부터 신호가 생성되며, 세 번째부터 결과 검증이 붙습니다.

## 6. iv30 단위 (백분율 포인트)

CBOE `iv30`은 `42.686`처럼 백분율 포인트로 옵니다. 1SD 계산 시 반드시 소수로 변환:

```python
iv30 = iv30_raw / 100 if iv30_raw > 1 else iv30_raw
```

옵션별 `iv` 필드는 이미 소수(0~1)이므로 그대로 사용합니다.

## 7. 금리 등락 표기

`^TNX`/`^TYX`의 `change_pct`는 수익률의 **% 변화**일 뿐입니다 (예: -4.55%처럼 보여도 실제로는 -19bps). 브리핑에는 **%p 또는 bps**로 표기해야 오해가 없습니다.

## 8. 텔레그램 전달 시 토픽 ID 유실

크론 배달 대상을 `telegram:<chat_id>`로만 지정하면 그룹 General로 가고, 토픽 정보가 사라집니다. 토픽으로 보내려면 반드시 `telegram:<chat_id>:<topic_id>` 형식을 사용하세요.

## 9. 표(markdown table)는 모바일에서 잘림

텔레그램 브리핑에는 표를 쓰지 않고 **한 줄 항목 + 섹션 사이 빈 줄** 형식을 사용합니다. 옵션처럼 항목이 많은 섹션은 맨 마지막에 배치합니다.

## 10. Windows 경로 (MSYS bash에서 실행 시)

- 네이티브 프로그램에 `/tmp/...` 같은 MSYS 경로를 주면 실패합니다 → `C:/...` 형식 사용
- 스크래치 파일은 `/tmp` 대신 `%LOCALAPPDATA%\Temp` 사용
- `time.sleep` 기반 백오프가 들어간 대량 수집은 크론 타임아웃을 고려해 설계할 것 (61종 ≈ 3분)
